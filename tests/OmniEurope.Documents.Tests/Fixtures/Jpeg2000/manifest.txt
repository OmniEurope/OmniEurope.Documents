# group sample expected-planes tolerance reference cross-checks
#
# Each expected file holds the decoded planes of the sample (its colour channels in order, then its opacity channel),
# each at its own size and sample depth, as concatenated binary PGM images; signed samples are stored offset by half
# their range. The planes were produced once by independent reference decoders, never run by the tests:
#   reference-a  an independent PDF renderer drawing the sample as a JPXDecode image, one pixel per sample (it gives
#                grey or RGB pixels only, so opacity comes from the source image of the sample);
#   reference-b  an independent JPEG 2000 decoder giving each component's samples raw, at their own depth;
#   source       the image the lossless sample was encoded from (where neither reference decodes the sample).
# The reference column names where the planes come from; the cross-checks give, for each source, how many samples
# of this decoder's output differ from it and by how much at most (differing/largest). reference-a is compared on
# 8-bit pixels: it scales 4- and 16-bit samples another way (one level), converts CMYK and Lab its own way, renders
# 4:1:0 and 4:4:0 subsampled sYCC blank, and draws lossy-rgba-u8-prog0-layers1-res6-mct.jp2 and
# lossless-rgba-u8-prog0-tile-part-index-overflow.jp2 wrongly. reference-b ignores the region of interest shift of
# lossless-RGN.jp2 and fails on three samples (cross-check "fails").
# reference-a-roundtrip: the colour planes, written uncompressed in a PDF as DeviceCMYK, render pixel for pixel as
# reference-a renders the sample (neither reference gives the CMYK planes of a five-component image).
#
# Tolerance: lossless samples (reversible 5-3 wavelet) must decode exactly. The irreversible 9-7 wavelet is computed
# in real numbers, and the standard sets no bit-exact result for it; the two references themselves differ by one
# level on these samples, so one level is allowed there.
#
# Files ending in .rgb.pgm hold reference-a's RGB rendering of the sYCC samples (4:2:0 and 4:2:2), against which
# the colour conversion is checked within one level (rounding of the conversion).
